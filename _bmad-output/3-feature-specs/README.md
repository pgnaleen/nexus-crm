# 3 — Feature Specs

**How one feature must behave** — the detailed contract, written before building and frozen once
approved. Produced by `bmad-spec`; consumed by `bmad-dev-story` and `bmad-code-review` (a spec is
what lets the review's Acceptance Auditor run at all).

These are **inputs, not work items.** A spec being present says nothing about whether the feature
is built — check [../2-current-work/sprint-status.yaml](../2-current-work/sprint-status.yaml).
