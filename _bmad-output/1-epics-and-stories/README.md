# 1 — Epics and Stories

**What we're building.** An *epic* is a big chunk of capability; a *story* is one user-visible
outcome inside it, written as "As a… I want… so that…" plus acceptance criteria.

These files define the work. They do **not** track whether it's done — that's
[../2-current-work/sprint-status.yaml](../2-current-work/sprint-status.yaml). If a status marker
in here disagrees with that file, the tracker wins; these markers went stale once already.

`feature-development-guideline.md` is the checklist every new feature must satisfy.
