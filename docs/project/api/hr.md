## Employees (`backend/src/modules/employees/employees.controller.ts`)

Employee Management epic. Response is `EmployeeListItemResponse`, a deliberately narrow
directory-listing shape (id, fullName, title, departmentId/departmentName, employmentStatus) —
excludes every Confidential field the `Employee` entity/`IEmployee` type carries (NIC/passport,
base salary, etc.), same shape used for both the list and the create response. The dropdown/picker
listing used elsewhere in the app (Deal owner field, Relationship party referral field) lives in
`PickersController` (`GET /pickers/employees`, see `pickers-and-auth.md`), not here.
**2026-07-27**: `profilePhotoUrl`/`cvUrl` (wherever present below) are now S3 keys (see
`platform.md`'s Uploads section); responses that include them also carry fresh
`profilePhotoDisplayUrl`/`cvDisplayUrl` (signed, generated per response) for rendering.

## Certifications (`backend/src/modules/certifications/certifications.controller.ts`)

Employee Management epic, Stories 1.12–1.14. Self-service certification claims. All routes below
are **auth-only** (no RBAC permission — the global `JwtAuthGuard` is the gate): every route
resolves the caller's OWN employee (`EmployeesService.findByUserId`) and operates only on their own
rows, same posture as `GET /employees/me` and `POST /users/me/change-password`. A caller whose
account isn't linked to an employee (Story 1.6) gets `403`. HR review (verify/reject, Story 1.13)
and the staffing search (Story 1.14) will add their own permission-gated routes here later.
**2026-07-27**: `evidenceFileUrl` on every response below is now an S3 key (see `platform.md`'s
Uploads section); responses that include it also carry a fresh `evidenceFileDisplayUrl` (signed,
generated per response) for rendering — `evidenceFileUrl` itself is submit-back-safe, never a URL.
